Objective

SSL/TLS Overview

Study and simulate the basic architecture and working of the SSL/TLS protocol between a client and a server. Simulate the SSL/TLS handshake process and demonstrate the sequence of cryptographic messages exchanged between the client and server. This includes understanding the differences between TLS 1.2 and TLS 1.3, observing how Perfect Forward Secrecy is achieved through Ephemeral Diffie-Hellman (ECDHE) key exchanges, and verifying digital certificates to defend against Man-in-the-Middle (MITM) attacks.

Theory

Theory

What is SSL/TLS?

Transport Layer Security (TLS), and its now-deprecated predecessor, Secure Sockets Layer (SSL), are cryptographic protocols designed to provide communications security over a computer network. The primary goals are confidentiality (encryption), integrity (message authentication codes), and authentication (digital certificates).

Position in the Network Stack

TLS resides between the Application layer (e.g., HTTP) and the Transport layer (TCP). It wraps application data in an encrypted tunnel before passing it to TCP.

TLS Architecture

The TLS protocol consists of two main layers:

  • Handshake Protocol: Used to negotiate cipher suites, authenticate the server (and optionally the client), and securely exchange keying material before data transmission.
  • Record Protocol: Secures application data using the keys generated during the handshake. It fragments, compresses (optional), adds a MAC, and encrypts the data.
TLS 1.2 vs TLS 1.3: TLS 1.2 requires 2 Round-Trip Times (RTT) for a full handshake. TLS 1.3 optimizes this to 1-RTT by sending key shares directly in the ClientHello, drops obsolete ciphers, and encrypts more of the handshake.

Procedure
