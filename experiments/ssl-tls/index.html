Cryptographic Security Systems

SSL/TLS Overview

Simulate the SSL/TLS handshake protocol and demonstrate the sequence of cryptographic messages exchanged between a client and server.

Aim

Study and simulate the basic architecture and working of the SSL/TLS protocol between a client and a server. Simulate the SSL/TLS handshake process and demonstrate the sequence of cryptographic messages exchanged between the client and server. This includes understanding the differences between TLS 1.2 and TLS 1.3, observing how Perfect Forward Secrecy is achieved through Ephemeral Diffie-Hellman (ECDHE) key exchanges, and verifying digital certificates to defend against Man-in-the-Middle (MITM) attacks.

Theory

What is SSL/TLS?

Transport Layer Security (TLS), and its now-deprecated predecessor, Secure Sockets Layer (SSL), are cryptographic protocols designed to provide communications security over a computer network. The primary goals are confidentiality (encryption), integrity (message authentication codes), and authentication (digital certificates).

Position in the Network Stack

TLS resides between the Application layer (e.g., HTTP) and the Transport layer (TCP). It wraps application data in an encrypted tunnel before passing it to TCP.

TLS Architecture

The TLS protocol consists of two main layers:

  • Handshake Protocol: Used to negotiate cipher suites, authenticate the server (and optionally the client), and securely exchange keying material before data transmission.
  • Record Protocol: Secures application data using the keys generated during the handshake. It fragments, compresses (optional), adds a MAC, and encrypts the data.

Other sub-protocols include the Alert Protocol for errors/warnings and ChangeCipherSpec to signal the transition to encrypted communication.

Key Concepts

  • Certificates & CAs: Digital certificates bind a public key to an entity's identity, verified by a trusted Certificate Authority (CA) via a chain of trust.
  • Cipher Suites: A named combination of authentication, encryption, MAC, and key exchange algorithms (e.g., TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256).
  • Key Derivation: Client and Server Randoms, combined with a shared Pre-Master Secret (e.g., via ECDHE), generate a Master Secret, which yields symmetric session keys for encryption and MACs.

TLS 1.2 vs TLS 1.3

TLS 1.2 requires 2 Round-Trip Times (RTT) for a full handshake. TLS 1.3 optimizes this to 1-RTT by sending key shares directly in the ClientHello, drops obsolete ciphers (like static RSA key exchange), and encrypts more of the handshake.

Procedure

  1. Go to the Simulation tab.
  2. Configure the simulation settings (TLS Version, Key Exchange, Certificate validity, Scenario).
  3. Use the Play button to start the automated handshake animation, or use Step Forward to walk through it manually.
  4. Observe the messages exchanged in the central network channel. Click on a message to inspect its payload (version, randoms, ciphers, key shares) in the Packet Inspector.
  5. Once the handshake completes, enter a plaintext message in the client terminal and send it to observe application data encryption.
  6. View the Event Log and Metrics Dashboard to analyze cryptographic operations and round trips.
  7. Try different failure scenarios (e.g., Expired Certificate, Man-in-the-Middle) to see how TLS defends against attacks.
